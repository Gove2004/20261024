# 看图：让多模态模型当眼睛

**Agent 自己看不到像素。** 任何"我改完了渲染，看起来应该没问题"的说法都是幻觉。
本仓库的所有视觉判断都必须走 `tools/vision.mjs`，把图交给多模态模型，用它的文字描述作为事实来源。

## 0. 铁律

1. **没跑过 vision 就不许说"视觉效果正常"。** 尤其改完 CSS / 渲染 / 贴图之后。
2. **只信可验证的项**：位置、重叠、裁切、缺失、对比度、字号、颜色混淆、和 prompt 不符。
   **不要信"好不好看""够不够高级"这类判断** —— 模型没有项目上下文，它说"像程序员美术"是它的先验，不是结论。
3. 视觉结论要**具体到可执行**："左上角计时器和星数条重叠" 有用；"整体偏暗" 没用。
4. 图里有中文时，模型可能读错字，**关键文案要回源码核对**，别把它的误读当 bug 去改。

## 1. 基本用法

```powershell
node tools/vision.mjs shots/02-arena.png
node tools/vision.mjs shots/02-arena.png -p "只回答：有没有元素重叠或被裁切？逐条列出来"
node tools/vision.mjs before.png after.png -p "对比两张图，说清楚改动的具体差异"
node tools/vision.mjs art/raw/slime-01.png -p "这张贴图有没有崩坏：多肢体、糊、色块断层、背景不透明？"
```

- Key 从 `.env.local` 读（**不提交**）。缺文件直接报错，不会去猜环境变量。
- 默认模型 `gemini-2.5-flash`，失败按序回退 `gemini-2.5-pro` → `chatgpt-4o-latest` → `claude-sonnet-4-5-20250929`。
- 指定模型：`-m gemini-2.5-pro`（复杂版式判断更准，慢 2–3 倍）。
- 一次可传多张图做对比（同一会话内模型能横向比较）。
- 单张 1280×720 截图约 5 秒、成本可忽略；**不要对同一张图反复问同一个问题**，改完再问。

## 2. 提问模板

**新画面第一轮**（建立基线）：

```
这是一款 2D 俯视角网页游戏的实机截图。用中文回答：
1) 画面里各元素分别在哪（主角、怪物、手牌、血条、计时器）；
2) 有没有元素重叠、错位、被裁切；
3) 可读性问题（对比度、字号、颜色混淆）；
4) 一句话：能直接给玩家看，还是必须改。
只描述你看到的，不要推测代码。
```

**回归检查**（改完之后，只问变动点）：

```
对比这两张图。上一版的问题是：<贴上一轮模型的原文结论>。
这一版是否修好了？逐条回答修好/没修好/更糟。
```

**贴图验收**：

```
这是一张游戏角色贴图。回答：1) 主体是什么、朝向哪边；2) 有没有多手多脚、五官错位、色块断层；
3) 边缘是否透明干净（有没有白边/黑边）；4) 和"半写实暗黑、DQ 风、2px 深色描边"匹配度如何。
```

## 3. 拿到结论之后

1. 结论里的**可执行问题**逐条改进代码，改完重跑 `node tools/smoke.mjs` 重新截图，再问一次。
2. 结论里的**审美评价**记到 `docs/` 里当参考，不要当作必须修。
3. 如果模型说"没看到怪物/UI 元素"——先确认截图时机（`smoke.mjs` 的截图点是否在对局中段），
   不要直接当成渲染 bug。

## 4. 已知限制

- 模型会**数错**密集小物体（只数得出大概），不要用它数场上怪物数量。
- 模型读不出像素级坐标，只给相对位置（"偏左上""居中"）。要对齐就用固定尺寸断言，别用眼睛。
- 图片走公网上传，**截图里不能有 Key、内网地址、个人信息**。本项目截图不含敏感内容，安全。
