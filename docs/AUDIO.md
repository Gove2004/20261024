# 游戏音频系统：持续主题 BGM + 信息型音效

> 当前方案继续使用 **100% WebAudio 程序合成**。BGM、音效、打击感全部由运行时的振荡器、噪声、滤波器和包络生成，不引入外部音频文件，保证提交体积小、授权清晰，音乐能随游戏阶段实时变化。

## 设计目标

音频用三句话概括：**可爱外壳、危险内核、持续推进**。

- 主题保持 D 弗里几亚的根音与动机，让玩家始终知道自己仍在同一场讨伐里。
- 游戏阶段只改变声部、密度和滤波亮度，不切换整首曲目，避免突兀静音。
- 音效优先传达召唤、命中、受伤、权能和结算等信息；高频事件节流，避免战斗变成噪声墙。

## 音频链路

```text
music ─▶ low-pass ─▶ compressor ─▶ master ─▶ destination
sfx   ───────────────────────────────┘
```

- `master` 默认 0.55，静音通过 `setMuted` 同时压低音乐与音效。
- `music` 默认 0.13，为战斗音效保留余量；重音效通过短暂 ducking 让操作反馈优先。
- 普通暂停时音乐降到 0.03；权能选择时降到 0.045。两者都会冻结音序器，恢复时从新的拍点开始。

## 自适应 BGM

- 120 BPM，D 弗里几亚，16 分音符一格，4 小节约 8 秒循环。
- 平和层保留低频 drone、和声 pad、远钟和短旋律。
- 紧张层逐步加入贝斯、底鼓、踩镲和琶音。
- 高潮层再加入军鼓与高八度回声。
- 分层使用 `setTargetAtTime` 平滑变化；所有层共享同一拍点，循环接缝不换曲、不长时间静音。
- `setUrgency(0..1)` 根据最后 60 秒的剩余时间推进心跳和音乐亮度；锅巴低血量时提高滤波开口，强化决战感。

## 状态映射

| 游戏状态 | 音乐行为 | 信息音效 |
| --- | --- | --- |
| 标题页 | 不创建 AudioContext，避免自动播放限制 | 无 |
| 开始/重开 | 用户手势中解锁并从第一拍起播 | 开局/波次提示 |
| 普通战斗 | 按局内时间自动推进三档层级 | 召唤、命中、技能、受伤 |
| 权能三选一 | 保留低音量氛围并冻结音序器 | 面板展开与确认 |
| 普通暂停 | 降至极低音量并冻结排期 | UI 操作反馈保留 |
| 胜利/失败 | BGM 约 2.6 秒淡出，接胜负动机 | 上行胜利/下行失败 |

## 浏览器策略

- 不创建 AudioContext 直到用户点击“开始讨伐”；这保证浏览器自动播放限制不会让整局静音。
- 移动端首次播放在用户手势回调中 `resume()`。
- 音序器使用 `AudioContext.currentTime` 提前排期，25ms 轮询只负责补排下一小段音符，不直接在定时器里卡点。

## 验证

```text
npm test
npm run build
node tools/audio-probe.mjs
node tools/smoke.mjs
node tools/mobile-probe.mjs
```

`audio-probe` 会检查安静窗口中的 BGM 调度和战斗音效增量；浏览器冒烟覆盖教程、权能三选一、结算和重开；移动端探针覆盖竖屏与横屏布局。

## 取舍

- 当前不引入外部音频文件，也不接入动画片头；游戏氛围由持续 BGM 与状态音效承担。
- 暂不做 3D 空间音和复杂混响；俯视 2D 玩法中，明确的事件音色比空间定位更有收益。
